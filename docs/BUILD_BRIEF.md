# 코드트리 학습 에이전트: 구현 지시서 (Claude Code용, 2026-11-18)

이 문서 하나만 읽고 작업을 시작할 수 있게 썼다.

## 0. 작업 방식

- 한국어로 보고한다. 설명은 짧게, 사실만.
- 단계(마일스톤)마다 커밋하고, 끝날 때마다 무엇을 했고 무엇을 확인하지 못했는지 적는다.
- 확인하지 않은 것을 됐다고 쓰지 않는다. 브라우저에서만 확인되는 항목은 "사용자 확인 필요" 목록으로 남긴다.
- 단계가 끝날 때마다 `docs/`에 결정 사항과 변경 내역을 기록한다.

## 1. 만드는 것

코드트리(codetree.ai) 문제 페이지 위에 넣었다 뺐다 하는 서랍형 크롬 확장(Manifest V3). 서버 없음.

- 코드 전에 6개 질문에 답하게 한다 (기본 켬, 질문마다 건너뛰기 가능)
- 막히면 힌트를 단계로 연다 (질문 → 방향 → 코드 한 줄 → 정답)
- 풀고 나면 걸린 질문, 몰랐던 것, 알게 된 것을 기록한다
- LLM은 사용자가 자기 계정으로 연결한다

## 2. 구조

| 부품 | 하는 일 |
|---|---|
| 콘텐츠 스크립트 | 문제 본문, 코드, 실행 결과를 읽는다. 서랍 UI를 페이지에 띄운다 (Shadow DOM으로 격리) |
| 서랍 UI | 화면 5개: 접힌 손잡이, 풀기 전, 막혔을 때, 풀고 난 뒤, 설정 |
| 백그라운드(서비스 워커) | LLM 호출, 저장 |
| LLM 연결부 | 연결 방식을 갈아 끼우는 인터페이스. 나머지 코드는 어떤 방식인지 모른다 |
| 저장소 | `chrome.storage.local`. 풀이 기록, 개념 기록, 설정 |
| 연결 프로그램 (선택, 나중) | 크롬 네이티브 메시징으로 PC의 Claude Code를 호출 |

핵심 원칙: **흐름은 코드가 쥐고, LLM은 한 번에 좁은 일 하나만 한다.**

- 답 채점: N번 질문의 답이 맞는지만 묻고 `{pass, feedback}`을 JSON으로 받는다
- 힌트: 누른 단계의 것만 생성한다. 1~2단계 응답에 코드 블록이 섞이면 걸러낸다
- 정리: 세션 기록에서 `gaps`와 `concepts`를 뽑는다
- 자유 질문이 5번 넘게 이어지면 "이제 코드를 쳐 보세요"로 넘긴다

권장 스택: TypeScript + Vite, UI는 가벼운 것(Preact 또는 순수 TS). 더 나은 선택이 있으면 이유를 적고 바꿔도 된다.

## 3. 코드트리 읽기 (실험으로 확인된 방법)

| 읽을 것 | 방법 | 상태 |
|---|---|---|
| 문제 본문, 예제, 제한 조건 | `document.body.innerText`. 로딩이 끝난 뒤 읽는다 | 확인됨 |
| 수식 원문 | `annotation[encoding="application/x-tex"]` (KaTeX) | 확인됨 |
| 작성 중인 코드, 언어 | `localStorage["ide-storage"]` → JSON의 `state.code`, `state.language` | 확인됨 |
| 코드 (예비) | `.monaco-editor[data-uri]` 요소의 React fiber에서 `getValue`를 가진 객체를 찾는다 (메인 월드 실행 필요) | 확인됨 |
| 실행 결과 | `innerText`에서 "나의 출력", "정답", 오류 메시지, "수행 시간", "메모리" | 확인됨 |
| 제출 및 채점 결과 | 미확인 | 사용자 확인 필요 |

주의:

- 페이지가 브라우저에서 그려지므로 일찍 읽으면 빈 값이 나온다. `MutationObserver`나 재시도로 기다린다.
- 화면 DOM의 에디터 줄(`.view-line`)은 보이는 줄만 있어서 쓰면 안 된다.
- 전역 `monaco` 객체는 없다.
- 라벨 요소 안에 아이콘이 같이 들어 있어, "글자만 있는 리프 요소" 조건으로는 라벨이 안 잡힌다. 텍스트 포함 여부로 찾는다.
- 실행 결과는 세 종류로 다룬다: 오류(오류 메시지만 뜸), 출력 불일치(나의 출력 ≠ 정답), 통과.
- 화면 폭이 좁아지면 코드트리가 실행·제출 버튼을 화면 구성에서 뺀다. 그래서 사이드 패널이 아니라 페이지 위에 겹치는 서랍으로 만든다. 페이지 폭을 바꾸는 CSS를 넣지 않는다.
- `ide-storage`의 이름과 구조는 코드트리 내부 사정이라 바뀔 수 있다. 읽기 코드는 한 파일에 모으고, 실패하면 예비 경로로 넘어가게 한다.
- 실행 결과가 뜬 화면의 `innerText` 끝부분 실제 예: `...4 9 14 19 24 \n5 10 15 20 25 \n\n\n상세 정보\n\n수행 시간\n\n48ms\n\n메모리\n\n16MB`. 오류일 때 예: `\nValueError: not enough values to unpack (expected 2, got 1)`.
- 결과가 없을 때 끝부분 예: `...(에디터 코드)\n테스트케이스\n결과\n코드 실행\n\n제출 및 채점`.
- 문제 URL 예: `https://www.codetree.ai/ko/trails/complete/curated-cards/<problemId>/description`

## 4. 6개 질문

| # | 질문 | 화면에 쓰는 짧은 이름 |
|---|---|---|
| 1 | 무엇이 입력되는가 | 입력 |
| 2 | 무엇을 어떤 형식으로 출력하는가 | 출력 |
| 3 | 규칙을 한 문장으로 말하면 | 규칙 |
| 4 | 작은 예제를 손으로 풀면 | 손풀이 |
| 5 | 출력 한 줄은 무엇에서 나오는가, 무엇을 몇 번 도는가 | 구조 |
| 6 | 경계 케이스와 크기는 | 경계 |

- 통과한 답은 한 줄로 접는다. 틀리면 정답을 주지 않고 되묻는 한 줄을 준다.
- 질문마다 "힌트"와 "건너뛰기"가 있다.
- 설명은 기본 한두 줄.

## 5. LLM 연결

설정에서 하나를 고른다. 순서대로 구현한다.

| 순서 | 방식 | 비고 |
|---|---|---|
| 1 | Claude API 키 | 가장 먼저. 키는 `chrome.storage.local`에만 둔다 |
| 2 | OpenAI API 키, Gemini API 키 | 같은 인터페이스로 추가 |
| 3 | Claude Code 경유 | 네이티브 메시징으로 `claude -p` 호출. 사용자가 자기 구독으로 로그인해 둔 Claude Code를 있는 그대로 부른다 |
| 4 | ChatGPT 로그인 | 개인 확장이 등록 가능한지 OpenAI 공식 문서에서 먼저 확인 |

지켜야 할 선:

- 우리 코드는 Claude.ai 로그인 화면을 띄우거나 구독 토큰을 받거나 보관하지 않는다.
- 저장소에 키를 넣지 않는다. 코드에 키를 심지 않는다.
- 각 회사 정책은 2026년에 여러 번 바뀌었다. 3, 4번을 구현하기 전에 공식 문서를 다시 읽고 `docs/`에 근거를 남긴다.

## 6. 기록 스키마 (schemaVersion 1, 고정)

원칙: 필드는 빼지 않는다. 값이 없으면 null. JSON이 원본이고 글(마크다운)은 출력 형식이다. 통계는 저장하지 않고 매번 계산한다.

풀이 기록 (문제를 한 번 풀 때마다 한 건. 다시 풀면 새 기록):

```json
{
  "schemaVersion": 1,
  "id": "codetree:intro-compare-two-grids:2026-11-18T16:08",
  "site": "codetree",
  "problemId": "intro-compare-two-grids",
  "title": "두 개의 격자 비교하기",
  "difficulty": "Easy",
  "language": "python",
  "startedAt": "2026-11-18T16:08:00+09:00",
  "finishedAt": "2026-11-18T16:20:00+09:00",
  "result": "passed",
  "questions": [
    { "q": 1, "state": "passed" },
    { "q": 2, "state": "failed" },
    { "q": 3, "state": "passed" },
    { "q": 4, "state": "skipped" },
    { "q": 5, "state": "failed" },
    { "q": 6, "state": "skipped" }
  ],
  "runs": { "total": 3, "errors": 0, "mismatches": 1 },
  "hints": { "maxLevel": 2, "answerRevealed": false },
  "gaps": [
    { "text": "print(리스트)는 대괄호와 쉼표까지 찍는다", "q": 2, "tag": "출력" }
  ],
  "concepts": ["print-unpack", "zip"],
  "reviewAt": "2026-11-20"
}
```

- null 허용: `difficulty`, `language`, `finishedAt`, `result`, `gaps[].q`, `gaps[].tag`, `reviewAt`
- `result`: `passed` / `gave_up` / null(진행 중)
- `questions`: 항상 6칸. `state`는 `passed` / `failed` / `skipped` / `not_reached`
- `hints.maxLevel`: 0~3
- `tag` 고정 목록: `리스트 동작` / `이터레이터` / `입력` / `출력` / `디버깅` / `코테 감각` / `2차원 순회`. 안 맞으면 null

개념 기록 (개념마다 한 건, 계속 갱신):

```json
{
  "schemaVersion": 1,
  "id": "zip",
  "name": "zip(a, b)",
  "rule": "같은 번째끼리 짝지어 하나씩 건네준다",
  "state": "explained",
  "firstSeenAt": "2026-11-18",
  "typedAt": null,
  "seenIn": ["codetree:intro-compare-two-grids:2026-11-18T16:08"]
}
```

- `state`: `explained`(설명만 들음) / `typed`(직접 쳐서 통과). null 허용: `rule`, `typedAt`

스키마 검증 코드와 테스트를 같이 만든다.

## 7. 화면과 디자인

시안: https://claude.ai/artifact/U97BJ991XwATjmPEqoAWM4 (열 수 없으면 아래 값으로 만든다)

화면 5개:

1. **접힌 손잡이:** 화면 가장자리에 28×64px, `<` 하나만. 클릭 또는 단축키로 서랍이 열린다.
2. **풀기 전:** 문제 제목, 3개 탭, 6개 질문(통과는 접힘, 현재 질문만 큰 카드), 진행 막대(2/6), 자유 질문창.
3. **막혔을 때:** 나의 출력과 정답을 나란히, 힌트 사다리, 코드 리뷰 3항목(맞는가, 읽기 쉬운가, 더 단순한 길이 있는가), 자유 질문창.
4. **풀고 난 뒤:** 걸린 질문 6칸, 몰랐던 것, 알게 된 것(직접 침 / 설명만 들음), 다음 할 일, "이 풀이는 내 기록에 저장됐습니다", 버튼 "이틀 뒤 다시 풀기"와 "내 기록 보기".
5. **설정:** 계정 연결(하나 선택), 서랍 위치(왼쪽/오른쪽), 단축키, 6개 질문 켜고 끄기, 내 기록(보기, 글로 복사하기).

동작:

- 서랍 폭 420px. 페이지 위에 겹친다. 페이지 폭을 건드리지 않는다.
- 열기/닫기: 손잡이 클릭, 단축키(기본 `Alt+Q`, 충돌 여부 확인 필요), 열린 상태에서 Esc와 바깥 클릭.
- 손잡이 숨기기: 툴바의 확장 아이콘 클릭.
- 기록은 자동 저장. 화면 용어는 "내 기록". 내부 용어(gap-map, 스키마, 마크다운)를 화면에 쓰지 않는다.

## 8. 단계

| 단계 | 내용 | 끝난 기준 |
|---|---|---|
| M0 | 저장소 뼈대, 빌드, 린트, 테스트 설정 | `npm run build`로 `dist/`가 나오고 크롬에 불러올 수 있다 |
| M1 | 코드트리 읽기 모듈 + 손잡이와 빈 서랍 | 문제 제목과 본문이 서랍에 보인다. 열고 닫힌다 |
| M2 | LLM 연결부 인터페이스 + Claude API 키 + 설정 화면 | 키를 넣고 연결 확인이 된다 |
| M3 | 풀기 전 화면: 6개 질문 채점, 힌트, 건너뛰기 | 한 문제를 6번까지 진행할 수 있다 |
| M4 | 풀이 기록 저장, 내 기록 보기, 글로 복사하기 | 스키마 검증 테스트 통과 |
| M5 | 막혔을 때 화면: 실행 결과 3종 감지, 힌트 사다리, 코드 리뷰 | 오류와 출력 불일치를 각각 인식한다 |
| M6 | 풀고 난 뒤 화면: 개념 기록, 다시 풀기 일정 | 개념이 `explained`에서 `typed`로 바뀐다 |
| M7 | 나머지 연결 방식 | 방식별로 근거 문서와 함께 |

이번 작업 범위: **M0부터 M4까지.** M5 이후는 사용자가 써 본 뒤에 진행한다.

## 9. 테스트와 확인

- 읽기 모듈은 저장해 둔 페이지 텍스트 표본(fixture)으로 단위 테스트한다. 표본이 없으면 3번의 확인된 구조대로 만든다.
- LLM 호출은 가짜 응답으로 테스트한다. 실제 키로 호출하는 테스트를 자동으로 돌리지 않는다.
- 매 단계 끝에 "사용자 확인 필요" 목록을 갱신한다. 예상되는 항목:
  - 실제 코드트리에서 서랍이 채널톡 버튼 등과 겹치는지
  - 서랍이 열린 상태에서 실행·제출 버튼이 그대로 있는지
  - `Alt+Q`가 다른 단축키와 겹치는지
  - 제출 및 채점 결과가 읽히는지

## 10. 하지 말 것

- 코드트리에 자동으로 코드를 제출하거나, 에디터 내용을 바꾸지 않는다. 읽기만 한다.
- 코드트리의 비공개 API를 호출하지 않는다. 화면에 있는 것만 읽는다.
- 사용자 계정 정보, 쿠키, 토큰을 읽거나 저장하지 않는다.
- 서버를 만들지 않는다. 사용 기록을 밖으로 보내지 않는다.
- 범위를 넓히지 않는다. 백준, LeetCode 지원은 이번 범위가 아니다(읽기 모듈을 사이트별로 분리해 두기만 한다).
