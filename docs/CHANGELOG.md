## 6칸 개편 구현 (2026-11-20)

- 질문 문구·쓰는 틀·흐린 예시·"왜 이 칸을 쓰나요?"(교수 검토 반영), 화면 순서 입력 → 출력 → 손풀이 → 규칙 → 구조 → 경계
- 채점 3단계(통과/보완 통과/다시), 세 번째 다시면 칸 답 공개 후 넘김, 입력·출력·경계는 두 번째부터 바로 정정, 계산 칸은 노력 수준 medium, 파이썬 맞춤
- 구조·경계는 라벨 붙은 작은 칸, 구조 횟수가 비면 됨/안 됨 비활성, 안 됨이면 줄이기 칸
- 칸 힌트를 문제 전체 힌트 단계에서 분리, 지시서 4절 표를 최종 문구로
- 테스트: 단위 89개, 브라우저 47개 항목 통과(가짜 페이지·가짜 응답)
- 확인 못 함: 실제 LLM이 새 판정 형식과 칸별 기준을 지키는지(실제 키 필요)

## 수정: 에디터 코드가 문제 본문에 섞이던 것, 힌트가 길던 것 (2026-11-20, 사용자 보고)

- 증상: 칸 힌트가 "학생 코드를 보면…"처럼 코드 이야기를 하고, 여러 줄·목록으로 길게 나왔다
- 원인: 코드트리 에디터(Monaco)는 띄어쓰기를 nbsp로 그려서, 본문을 자를 때 코드 첫 줄을 못 찾았다. 그래서 화면에 보이는 코드(와 줄 번호)가 "문제 본문"에 섞여 LLM에 넘어갔다(힌트 요청은 코드를 보내지 않는데도)
- 고침: 본문을 자르기 전에 nbsp를 공백으로 바꾸고, 코드 첫 줄을 공백 모양과 상관없이 찾는다. 본문 끝의 에디터 줄 번호(1, 2, 3…)를 뗀다. 힌트는 1단계 한 문장(140자), 2단계 두 줄(240자)로 잘라 보여 주고 목록 기호를 뗀다. 칸 힌트 프롬프트에 "이 칸 주제 안에서만, 코드 이야기 없이"를 넣었다
- 테스트 4개 추가(nbsp 표본 포함). 단위 93개, 브라우저 47개 항목 통과
