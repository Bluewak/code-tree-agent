# 결정 사항

## M0

- **빌드: Vite 대신 esbuild 직접 사용.** 확장은 진입점이 4개(백그라운드, 콘텐츠, 메인 월드, 설정 페이지)이고, 콘텐츠·메인 월드 스크립트는 ES 모듈로 실을 수 없어 IIFE 한 파일이어야 한다. Vite의 라이브러리 모드는 IIFE 진입점을 하나만 받으므로 설정이 복잡해진다. esbuild는 진입점마다 형식을 정할 수 있고 빌드가 1초 안에 끝난다. 테스트는 vitest(내부적으로 Vite)를 쓴다.
- **UI: Preact.** 화면 5개와 상태 전환이 있어 순수 TS보다 짧고, 번들이 작다(약 10KB).
- **글꼴:** `@fontsource/ibm-plex-sans-kr`(400, 600), `@fontsource/ibm-plex-mono`(400, 라틴)의 woff2를 `dist/fonts/`에 넣어 배포한다. 페이지 글꼴과 충돌하지 않게 `CSA Plex Sans KR`, `CSA Plex Mono`로 이름을 바꿔 등록한다. Shadow DOM 안의 `@font-face`는 크롬에서 적용되지 않으므로 `@font-face`만 문서 `<head>`에 넣는다.
- **아이콘:** 빌드 스크립트가 PNG를 직접 만든다(초록 바탕에 흰 `<`). 외부 이미지 파일 없음.
- **최소 크롬 버전 111:** 콘텐츠 스크립트의 `world: "MAIN"` 지원 때문.

## M1

- **읽기 모듈 구조:** `src/sites/types.ts`(사이트 공통 모양) / `src/sites/codetree/parse.ts`(화면 글자를 해석하는 순수 함수, 표본으로 테스트) / `src/sites/codetree/reader.ts`(DOM 접근). 코드트리 내부 구조(`ide-storage`, 라벨 글자)에 기대는 코드는 이 두 파일에만 있다. 백준·LeetCode는 `src/sites/<site>/`에 같은 모양으로 추가한다.
- **코드 읽기 순서:** `localStorage["ide-storage"]` → 실패하면 메인 월드 스크립트(`src/mainworld/`)에 `postMessage`로 물어 Monaco의 `getValue()` 값을 받는다. 메인 월드 스크립트는 값을 읽기만 한다.
- **기다리기:** `MutationObserver`로 화면 글자가 600ms 동안 바뀌지 않을 때 읽는다(최대 15초).
- **본문 자르기:** 제목이 처음 나오는 곳부터, 에디터 코드 첫 줄 또는 "테스트케이스" 라벨 앞까지. 8000자 넘으면 자른다.
- **실행 결과(M5에서 화면에 씀, 해석은 미리 구현):** 마지막 "테스트케이스" 라벨 뒤만 본다. 오류 줄(`...Error:`, Traceback, 컴파일/런타임 에러) → `error`, "나의 출력"과 "정답"이 있으면 비교해 `pass`/`mismatch`(줄 끝 공백 무시), "수행 시간"만 있으면 `pass`.
- **Shadow DOM은 open 모드.** closed로 해도 페이지 스크립트가 `attachShadow`를 먼저 가로채면 열 수 있어 실익이 없고, open이어야 Playwright 확인 테스트가 안을 읽을 수 있다. 서랍 DOM에는 API 키가 들어가지 않는다(키 입력은 확장 설정 페이지에서만).
- **겹치기:** 호스트 요소는 크기 0의 `position: fixed`. 손잡이와 서랍만 `position: fixed`로 그린다. 페이지 CSS를 바꾸지 않는다.
- **닫기:** Esc(창 캡처 단계), 바깥 `pointerdown`(이벤트 경로에 서랍 호스트가 없으면 닫음), 닫기 버튼, 단축키.
- **단축키:** `chrome.commands`(기본 `Alt+Q`). 백그라운드가 받아 탭에 `drawer.toggle`을 보낸다. 사용자는 `chrome://extensions/shortcuts`에서 바꿀 수 있다.
- **손잡이 숨기기:** 툴바 아이콘 클릭 → 설정 `handleHidden` 토글. 숨겨도 단축키로는 열린다.
- **SPA 이동:** 0.8초마다 주소를 비교해 바뀌면 문제를 다시 읽는다.
- **키 입력 격리:** 서랍 안의 키 이벤트는 Shadow DOM 밖으로 전파하지 않는다(코드트리 단축키 오작동 방지). Esc만 예외.

## M2

- **연결부 인터페이스:** `LlmProvider.complete({ system, messages, maxTokens?, jsonSchema? }) → string` 하나뿐이다(`src/llm/types.ts`). 흐름(채점, 힌트, 대화)은 `src/core/`가 쥐고 연결부는 글자만 주고받는다. 새 방식은 `src/llm/registry.ts`의 `createProvider`에만 추가한다.
- **Claude API:** 공식 SDK `@anthropic-ai/sdk`를 서비스 워커에서 `dangerouslyAllowBrowser: true`로 쓴다(사용자가 자기 키를 자기 브라우저에 넣는 구조라 허용). 호스트 권한은 `https://api.anthropic.com/*` 하나.
- **모델:** 기본 `claude-opus-5-5`. 설정 페이지에서 Sonnet 5.5, Haiku 5.5로 바꿀 수 있다. 일이 좁고 짧아 `output_config.effort: "low"`로 보낸다.
- **거절(refusal) 대비:** Opus 5.5/Sonnet 5.5에는 서버 쪽 대체 모델(`fallbacks: "default"`, 베타 `server-side-fallback-2026-07-01`)을 켠다. 그래도 거절이면 "표현을 바꿔 다시" 안내.
- **JSON 응답:** 채점처럼 모양이 정해진 응답은 `output_config.format`(JSON 스키마)을 쓴다. 그래도 받는 쪽에서 다시 검사한다(M3).
- **키 입력 위치: 서랍이 아니라 확장 설정 페이지(`options.html`).** 서랍은 코드트리 페이지 안에 그려지므로, 키를 거기서 입력받으면 페이지 스크립트가 입력창을 읽을 수 있다. 확장 설정 페이지는 확장 자신의 주소라 페이지와 분리된다. 서랍 설정 화면에는 연결 상태와 "키 넣기" 버튼(설정 페이지 열기), "연결 확인"만 둔다.
- **키 보관:** `chrome.storage.local`의 `secrets` 칸. 백그라운드만 읽고, 콘텐츠 스크립트에는 "있음/없음"만 보낸다. 키 저장 요청(`llm.setKey`)은 확장 페이지에서 온 것만 받는다(`sender.url`이 확장 주소인지 확인).
- **오류 문구:** 키 없음 / 키 틀림 / 한도 / 네트워크 / 거절 / 준비 중을 구분해 한 줄로 보여 준다.
- **빌드:** 백그라운드 번들이 SDK 때문에 커서(약 1MB) 빌드 때 압축(minify)한다. `npm run watch`에서는 압축하지 않고 소스맵을 넣는다.

## M3

- **흐름은 코드가 쥔다:** `src/core/session.ts`의 순수 함수(`applyGrade`, `skipQuestion`, `addHint`, `checkFreeAsk`, `addChat`)만 상태를 바꾼다. 화면은 이 함수를 부를 뿐이고, LLM은 `src/core/tasks.ts`의 좁은 일(채점, 힌트, 자유 질문)만 한다.
- **채점:** N번 질문 하나만 묻는다. 통과 기준은 질문마다 정해 둔 문장(`questions.ts`의 `criteria`)을 LLM에게만 보낸다. 응답은 JSON 스키마(`{pass, feedback}`)로 받고, 받는 쪽에서 다시 검사한다(코드 울타리·앞뒤 말 허용, 모양이 다르면 오류). 통과면 feedback이 "한 줄 요약"이 되어 질문이 접힌다. 틀리면 feedback이 "되묻는 한 줄"이 되고 그 자리에 머문다. feedback 안의 코드는 지운다.
- **질문 상태(기록용) 의미:** `passed` 한 번에 통과 / `failed` 한 번이라도 틀림(나중에 통과하거나 건너뛰어도 `failed`. "걸린 질문"을 남기기 위해) / `skipped` 틀린 적 없이 건너뜀 / `not_reached` 손대지 않음. 화면 진행은 별도 값(`resolved`)으로 한다. 진행 막대는 통과+건너뛴 수.
- **질문 힌트:** 질문마다 1단계(되묻는 질문) → 2단계(방향)까지만 연다. 1~2단계 응답의 코드 블록과 코드처럼 보이는 줄은 걸러 낸다. 걸러서 남는 게 없으면 힌트를 쓴 것으로 치지 않고 다시 누르게 한다. 기록의 `hints.maxLevel`은 받은 가장 높은 단계(0~3), 4단계(정답)를 받으면 `answerRevealed: true`.
- **자유 질문 5번 제한:** 질문에 답하거나 건너뛰지 않고 자유 질문만 5번 이어지면 6번째부터는 LLM을 부르지 않고 "이제 코드를 쳐 보세요"를 보여 준다. 질문에 답하거나 에디터 코드가 바뀌면 다시 물을 수 있다.
- **입력:** 답 입력창에서 Ctrl/⌘+Enter로 확인, 자유 질문은 Enter로 보내기(Shift+Enter 줄바꿈, 한글 조합 중에는 보내지 않음).
- **연결 안 됨:** 풀기 전 화면 맨 위에 "계정을 연결하면…" 안내와 "연결하기"(설정 페이지) 버튼. 연결 없이도 건너뛰기는 된다.
- **문제 본문:** 풀기 전 화면에서는 접어 둔다(펼치기 가능).

## M4

- **저장 칸(chrome.storage.local):** `records`(풀이 기록, id → 기록), `active`(문제별 진행 중인 풀이의 작업 상태, 이어 풀기용), `settings`, `secrets`. 개념 기록(`concepts`)은 M6에서 쓴다. 통계는 저장하지 않는다.
- **원본은 JSON 풀이 기록.** 화면 작업 상태(답 글, 요약, 자유 질문 대화)는 `active`에만 두고 기록 스키마에는 넣지 않는다(스키마 고정). 풀이를 끝내면 `active`에서 지운다.
- **언제 기록하나:** 손을 댄 뒤부터(질문에 답·건너뛰기·힌트·자유 질문·끝내기). 문제 페이지를 열기만 하면 기록하지 않는다. 바뀔 때마다 0.4초 모아 자동 저장한다.
- **검증:** `src/storage/schema.ts`의 `validateAttempt`/`validateConcept`. 필드가 빠지거나(값이 없으면 null), 정해지지 않은 필드가 있거나, 열거값·날짜 형식·6칸 순서·id 형식이 틀리면 저장하지 않고 오류를 보여 준다. 저장된 값을 읽을 때도 검사를 통과한 것만 쓴다.
- **id:** `codetree:<problemId>:<startedAt 앞 16자>`(분 단위). 같은 분에 "처음부터 다시 풀기"를 누르면 id가 겹치므로 새 풀이의 시작 시각을 다음 분 0초로 둔다.
- **result:** M5(실행 결과 감지) 전이라 "풀고 난 뒤" 화면의 "다 풀었어요"(passed) / "그만할래요"(gave_up) 버튼으로 정한다. 누르면 `finishedAt`이 찍힌다.
- **아직 비는 필드:** `gaps`, `concepts`는 빈 배열, `reviewAt`은 null, `runs`는 0. M5(실행 횟수), M6(몰랐던 것·개념·다시 풀기)에서 채운다. `difficulty`는 본문 앞부분에 "Easy/Medium/Hard/쉬움/보통/어려움"이 한 줄로 있으면 넣고, 없으면 null.
- **글로 복사하기:** 기록 전체를 마크다운 글로 만들어 클립보드에 넣는다(페이지가 클립보드 API를 막으면 `execCommand("copy")`로). 화면에는 "글로 복사하기"라고만 쓴다.
- **동시 저장:** 탭 여러 개에서 저장이 겹쳐 덮어쓰지 않게 백그라운드에서 저장을 한 줄로 세운다.

## 리셋 (2026-11-20, 사용자 요청)

- **처음부터 다시(풀기 전 화면 맨 아래):** 손댄 풀이가 있을 때만 보인다. 한 번 더 묻고 실행한다(서랍 안에서 묻고, 브라우저 확인 창은 쓰지 않는다).
  - 진행 중인 풀이: 그 풀이 기록과 이어 풀기 상태를 지우고 1번부터. "다시 풀면 새 기록" 원칙은 끝낸 풀이에만 적용한다(안 끝난 풀이를 버리는 것은 기록할 가치가 없다고 봄).
  - 끝낸 풀이: 기록은 남기고 새 기록으로 시작(기존 "처음부터 다시 풀기"와 같음).
- **내 기록:** 기록마다 "이 기록 지우기", 맨 아래 "모든 기록 지우기". 둘 다 한 번 더 묻는다. 모두 지워도 설정과 API 키는 남긴다. 지금 서랍에서 풀던 풀이의 기록을 지우면 서랍도 새 풀이(0/6)로 바뀐다(메모리에 남은 풀이가 자동 저장으로 기록을 되살리지 않게).
- **지우기와 저장의 순서:** 지우기도 저장과 같은 줄(백그라운드 직렬 큐)에 세운다. 지우기 전에 아직 보내지 않은 자동 저장은 취소한다.
- **기록 id 겹침(버그 수정):** id가 분 단위라 끝낸 풀이와 같은 분에 새 풀이를 시작하면 끝낸 기록이 덮어써졌다(M4부터, 새로고침 직후에도 가능). 새 풀이의 시작 시각을 "이 문제의 가장 늦은 기록의 다음 분 0초 이후"로 정한다(`nextStartTime`). 저장할 때도 같은 id에 시작 시각이 다른 기록이 있으면 덮어쓰지 않고 오류를 낸다.
