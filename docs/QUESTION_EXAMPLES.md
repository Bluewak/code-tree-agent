# 6개 질문 개편안: 실제 문제로 맞춰 보기 (초안, 2026-11-20)

개편안(세 검토 합본)의 6개 질문을 입문 문제 7개에 적용해 보고, 여기서 "답을 어떻게 쓰면 되는지"와 "채점을 어떻게 하는지"의 범용 가이드를 뽑았다.

- 문제 조건은 웹 검색으로 확인했다(백준 원문 페이지는 직접 열지 못했고 풀이 글들에서 교차 확인). 2884의 H·M 범위는 검색으로 확인하지 못해 알려진 값(0~23, 0~59)을 썼다.
- 코드트리 문제는 검색되지 않고 이 개발 환경에서 사이트 접속이 막혀 있어, 지시서의 격자 문제 1개와 같은 수준의 백준 입문 문제를 썼다.
- 문제 원문은 옮기지 않고 한 줄로 요약했다.

## 대상 문제 (유형이 겹치지 않게)

| 기호 | 문제 | 유형 | 요약 |
|---|---|---|---|
| A | 코드트리 "두 개의 격자 비교하기" | 2차원 순회 | n×m 격자 두 개, 같은 칸이 같으면 0 다르면 1을 n줄에 출력 (1≤n,m≤100) |
| B | 백준 2438 별 찍기 - 1 | 패턴 출력 | N(1~100)을 받아 i번째 줄에 별 i개 |
| C | 백준 2562 최댓값 | 누적 + 위치 | 9줄에 자연수 하나씩, 최댓값과 그 위치(몇 번째)를 두 줄로 |
| D | 백준 10818 최소, 최대 | 큰 입력 + 음수 | N(≤100만), 다음 줄에 정수 N개(-100만~100만), 최솟값 최댓값을 한 줄에 |
| E | 백준 10988 팰린드롬인지 확인하기 | 문자열, 반복 없이 가능 | 소문자 단어(길이 1~100), 회문이면 1 아니면 0 |
| F | 백준 2675 문자열 반복 | 여러 테스트 케이스 | T개 케이스, 각 줄에 R과 S, S의 글자마다 R번씩 늘어놓기 |
| G | 백준 2884 알람 시계 | 조건 분기 + 경계 | H M을 받아 45분 이른 시각을 H M으로 |

## 문제별 적용

표의 "통과하는 답"은 입문자가 쓸 법한 짧은 답이다. "흔한 틀린 답 → 피드백"은 개편안의 피드백 규칙(1번째는 위치 짚기, 1·2·6번은 2번째에 정정)을 따른 예다.

### A. 두 개의 격자 비교하기

(예제는 개발용 가짜 페이지의 것. 실제 코드트리 예제는 확인하지 못함)

| 질문 | 통과하는 답 | 흔한 틀린 답 → 피드백 |
|---|---|---|
| 1 입력 | 첫 줄: 정수 n m / 다음 n줄: 정수 m개씩 → a / 다음 n줄: 같은 형식 → b | "n, m, 격자 2개" → "격자 한 줄에 무엇이 몇 개 있나요?" |
| 2 출력 | n줄, 줄마다 0/1을 m개, 공백 구분 | "격자를 출력" → "'출력 형식'에서 한 줄에 몇 개를 무엇으로 구분하나요?" |
| 3 규칙 | 같은 칸의 a, b가 같으면 0, 다르면 1 | (거의 안 틀림) |
| 4 손풀이 | 예제(a: 1 2 / 3 4, b: 1 2 / 3 5)의 b 마지막 값 5를 4로 바꾸면 출력 둘째 줄 둘째 값이 1→0 | 출력 위치를 잘못 짚음 → "출력의 몇 번째 줄 몇 번째 값인지 다시 세어 보세요" |
| 5 구조 | 준비: 없음 / 반복: 줄 i는 0~n-1, 칸 j는 0~m-1, 비교값을 모음 / 출력: 줄이 끝날 때마다 공백으로 이어서 | "줄 목록을 출력" → (파이썬) "목록을 그대로 print하면 대괄호와 쉼표가 찍혀요. 한 줄을 어떻게 만들까요?" |
| 6 경계 | 가장 작은 입력: 1×1, 5와 5 → 0 | (특별한 함정 없음. "특별히 없음"도 통과) |

### B. 별 찍기 - 1

| 질문 | 통과하는 답 | 흔한 틀린 답 → 피드백 |
|---|---|---|
| 1 입력 | 첫 줄: 정수 N | (거의 안 틀림, 10초) |
| 2 출력 | N줄, i번째 줄에 별 i개, 구분 없이 붙여서 | "별 N개" → "'출력 형식'을 보면 줄마다 별 개수가 같나요?" |
| 3 규칙 | i번째 줄은 별을 i개 | (2번 답과 거의 같음: 아래 관찰 1) |
| 4 손풀이 | 예제 N을 5→3으로 바꾸면 3줄, 마지막 줄 별 3개 | 4줄로 적음 → "3줄째에서 끝나는지 세어 보세요" |
| 5 구조 | 반복: i는 1~N, 줄마다 별 i개를 출력 | "i는 0~N-1, 별 i개" → "첫 줄에 별이 몇 개 찍히나요?" (0부터 세면 첫 줄이 빈 줄) |
| 6 경계 | 가장 작은 입력: N=1 → `*` 한 줄 | |

### C. 최댓값 (값과 위치)

| 질문 | 통과하는 답 | 흔한 틀린 답 → 피드백 |
|---|---|---|
| 1 입력 | 9줄, 줄마다 자연수 하나 (100 미만) → 9개를 nums로 | "한 줄에 9개" → "'입력 형식'에서 한 줄에 몇 개가 들어오나요?" (이걸 틀리면 `input().split()` 한 번으로 받으려다 막힘) |
| 2 출력 | 2줄: 첫 줄 최댓값, 둘째 줄 위치 | "한 줄에 둘" → 2번째에 정정 |
| 3 규칙 | 가장 큰 수, 위치는 1부터 센 번째 | "가장 큰 수의 인덱스" → "예제에서 85는 몇 번째라고 하나요? 0번째부터 세나요?" |
| 4 손풀이 | 예제의 85를 10으로 바꾸면 최댓값 74, 위치 6 | 위치를 5로 적음(0부터 셈) → "몇 번째인지 1부터 다시 세어 보세요" |
| 5 구조 | 준비: 최대=첫 수, 위치=1 / 반복: 2~9번째 수, 더 크면 둘 다 바꿈 / 출력: 끝나고 두 줄 | 준비를 빠뜨림 → 보완 통과 + "처음 최댓값은 얼마로 두나요?" |
| 6 경계 | 최댓값이 첫 번째에 있을 때 → 위치 1 | |

### D. 최소, 최대 (큰 입력, 음수)

| 질문 | 통과하는 답 | 흔한 틀린 답 → 피드백 |
|---|---|---|
| 1 입력 | 첫 줄: 정수 N / 둘째 줄: 정수 N개가 한 줄에 공백 구분 (음수 가능) → nums | "N줄에 하나씩" → 위치 짚기 |
| 2 출력 | 1줄: 최솟값 최댓값, 공백 구분 | 순서를 바꿔 적음 → 2번째에 정정 |
| 3 규칙 | 가장 작은 수와 가장 큰 수 | |
| 4 손풀이 | 예제의 가장 큰 수를 -100으로 바꾸면 최솟값이 -100이 되고 최댓값은 그다음 큰 수 | |
| 5 구조 | 준비: 최소=최대=첫 수 / 반복: 나머지를 한 번씩 보며 갱신 / 출력: 끝나고 한 번. 가장 크면 100만 번, 파이썬도 충분 | "최대=0으로 시작" → "모든 수가 음수면 최댓값이 무엇으로 나오나요?" |
| 6 경계 | 모두 음수: -5 -3 → -5 -3 / N=1이면 같은 수 두 번 | "특별히 없음" → 통과(가장 작은 입력의 답으로). 다만 이 문제는 함정이 실제로 있어서 2단계 힌트가 음수를 가리키게 한다 |

|---|---|---|
| 1 입력 | 첫 줄: 소문자 단어 하나 (길이 1~100) → word | |
| 2 출력 | 1줄: 1 또는 0 | "YES/NO" → 1번째에 위치 짚기("'출력 형식'의 정확한 글자는?"), 2번째 정정 |
| 3 규칙 | 뒤집어도 같으면 1, 아니면 0 | |

### F. 문자열 반복 (여러 테스트 케이스)

| 질문 | 통과하는 답 | 흔한 틀린 답 → 피드백 |
|---|---|---|
| 1 입력 | 첫 줄: 정수 T / 다음 T줄: 정수 R과 문자열 S, 공백 구분 | "R과 S" (T를 빠뜨림) → "첫 줄의 수는 무엇인가요?" |
| 2 출력 | 케이스마다 1줄, 글자를 붙여서 | |
| 3 규칙 | S의 글자마다 R번씩 이어 붙임 | "S를 R번 반복" → "ABC를 2번 반복하면 ABCABC인데, 예제 출력도 그런가요?" |
| 4 손풀이 | 예제 첫 케이스 R을 3→2로 바꾸면 AABBCC | |
| 5 구조 | 반복: 케이스 T번 / 그 안에서 S의 글자마다 R번 / 출력: 케이스가 끝날 때마다 한 줄 | 케이스 반복을 빠뜨림 → "케이스가 여러 개면 무엇을 몇 번 도나요?" |
| 6 경계 | R=1이면 S 그대로 | |

### G. 알람 시계 (조건 분기)

| 질문 | 통과하는 답 | 흔한 틀린 답 → 피드백 |
|---|---|---|
| 1 입력 | 첫 줄: 정수 H M (0~23, 0~59) | |
| 2 출력 | 1줄: H M, 공백 구분 | |
| 3 규칙 | 분에서 45를 빼되, 모자라면 시를 1 줄이고 분에 60을 더함 | "45분을 뺌" → "10시 10분에서 45분을 빼면 분이 어떻게 되나요?" |
| 4 손풀이 | 예제 10 10을 0 30으로 바꾸면 23 45 | "−1 45" → "시가 0일 때 1을 빼면 몇 시가 되나요?" (4번에서 바로 함정이 드러남) |
| 5 구조 | 반복 없음: 분이 45 이상이면 빼기, 아니면 시 하나 줄이고(0시면 23시) 분+15 / 출력 한 번 | |
| 6 경계 | 0시 30분 → 23 45 | "특별히 없음" → 2단계 힌트가 자정을 가리키게 한다 |

## 관찰: 어디서 잘 맞고 어디서 어색했나

1. **패턴 문제(B)에서는 2 출력과 3 규칙이 사실상 같다.** "i번째 줄에 별 i개"가 출력 형식이자 규칙이다. → 2번에서 "줄마다 개수가 줄 번호에 따라 달라짐"까지 쓰면 3번은 같은 말을 한 줄로 써도 통과시킨다(앞 답 요약이 보이므로 "위와 같음"도 인정).
2. **반복이 없는 문제(E, G)에서는 5 구조가 "분기"를 묻게 된다.** "반복"이라는 말 때문에 입문자가 억지로 반복을 지어낼 수 있다. → 5번 칸 이름을 "준비 / 반복 또는 갈림길 / 출력"으로 바꾼다.
3. **4 손풀이는 바꾸는 값에 따라 배우는 게 달라진다.** G에서 0시로 바꾸면 자정 함정을 4번에서 바로 만나지만, 11시로 바꾸면 그냥 빼기 연습이다. → 강제하지 않고 1단계 힌트에서 "규칙이 갈라지는 값(조건이 바뀌는 쪽)으로 바꿔 보면 더 많이 배워요"라고만 권한다.
4. **6 경계에서 "특별히 없음"을 받으면, 진짜 함정이 있는 문제(D 음수, G 자정)에서 그냥 지나칠 수 있다.** → "특별히 없음"은 통과시키되, 채점 LLM이 이 문제에 실제 함정이 있다고 보면 피드백에 "하나만 더: 모든 수가 음수면?" 같은 한 줄을 붙인다(판정은 통과 유지).
5. **1 입력은 모든 유형에서 가치가 있었다.** "한 줄에 여러 개"와 "여러 줄에 하나씩"(C와 D)의 차이, 테스트 케이스 수 T(F)처럼 실제로 코드를 막는 지점을 잡는다.
6. **3 규칙은 위치 표현을 빼도 문제가 없었다.** 다만 위치 자체가 출력인 C는 "몇 번째(1부터)"가 규칙에 들어가야 한다. → "출력에 위치가 있으면 몇부터 세는지까지"를 통과 기준에 둔다.
7. **5 구조의 "가장 크면 몇 번" 조건부 질문은 D에서만 의미가 있었다.** 나머지는 제한이 작아 묻지 않는 게 맞다. 기준: 입력 크기 제한이 10만 이상일 때만 묻는다.

## 범용 가이드 (질문별 "이렇게 쓰면 된다"와 채점 규칙)

### 답 쓰는 법 (학생에게 보여 줄 한 줄 안내)

| 질문 | 쓰는 법 | 짧게 쓰는 요령 |
|---|---|---|
| 1 입력 | 줄 단위로 "몇째 줄: 무엇 몇 개, 종류 → 이름" | `/`로 줄 구분. 같은 형식이 반복되면 "같은 형식" |
| 2 출력 | "몇 줄 / 한 줄에 무엇 몇 개 / 무엇으로 구분" | 줄마다 개수가 다르면 "i번째 줄에 i개"처럼 |
| 3 규칙 | "~이면 ~" 또는 "~를 ~해서" 한 문장 | 출력에 위치가 있으면 몇부터 세는지 |
| 4 손풀이 | "예제 1의 [무엇]을 [값]→[값]으로 바꾸면 출력 [어디]가 [값]→[값]" | 조건이 갈라지는 쪽으로 바꾸면 더 배움 |
| 5 구조 | "준비: … / 반복 또는 갈림길: … / 출력: 언제" | 반복은 "무엇을 처음~끝", 반복이 없으면 "없음"과 비교·조건 |
| 6 경계 | "[어떤 입력] → [답]" | 정말 없으면 "특별히 없음" |

### 채점 규칙 (LLM에게 줄 공통 + 질문별)

공통:
- 그 질문이 묻는 것만 본다. 앞 질문 내용을 요구하지 않는다. 앞 답과 같은 말이면 "위와 같음"도 인정.
- 더 써도 감점하지 않는다. 변수 이름은 무엇이든(파이썬 내장 이름이면 다른 이름을 권하는 한 줄만).
- 판정: 통과 / 보완 통과(빠진 것 하나를 짚되 넘어감) / 다시. "다시"는 그대로 코딩하면 틀리는 오류에만.
- 코드 한 줄을 써도 된다. 그 코드가 실제로 무엇을 하는지로 판단한다.

질문별 "다시"인 경우:

| 질문 | "다시" | 보완 통과 |
|---|---|---|
| 1 입력 | 줄 구성이 틀림(한 줄 ↔ 여러 줄), 개수·첫 줄의 수(T 등)를 빠뜨림, 정수/글자 종류가 틀림 | 범위를 안 적음 |
| 2 출력 | 줄 수, 한 줄 개수, 구분자, 정확한 글자(1/0, YES/NO), 순서 중 하나라도 틀림 | 없음(형식은 맞거나 틀리거나) |
| 3 규칙 | 계산이나 조건이 틀림, 출력에 위치가 있는데 세는 기준이 틀림 | 조건의 한쪽만 씀("45 빼기"만) → 다른 쪽을 짚고 다시(G처럼 결과가 틀리면 "다시") |
| 4 손풀이 | 바뀐 출력 값이 틀림, 예제를 그대로 씀 | 출력의 어디인지 안 적음 |
| 5 구조 | 반복 범위가 틀려 첫 줄·마지막이 빠짐/넘침, 초깃값 때문에 틀림(최대=0과 음수), 케이스 반복 누락 | 준비를 빠뜨렸지만 결과에 영향 없음 |
| 6 경계 | 고른 경우의 답이 틀림 | "특별히 없음"인데 실제 함정이 있음 → 통과 + 한 줄 덧붙임 |

### 개편안에 반영할 수정 (이 실험에서 나온 것)

1. 5번 칸: "준비 / 반복 또는 갈림길 / 출력" (반복 없는 문제 대응)
2. 2·3번: 앞 답과 같은 말이면 "위와 같음" 인정 (패턴 문제 대응)
3. 3번 기준: 출력에 위치가 있으면 세는 기준까지
4. 4번 1단계 힌트: "규칙이 갈라지는 값으로 바꿔 보세요"
5. 6번: "특별히 없음"은 통과, 실제 함정이 있으면 한 줄 덧붙임
6. 5번 반복 횟수 질문: 입력 크기 제한이 10만 이상일 때만

# 골드 수준 문제로 맞춰 보기 (2026-11-20)

같은 6개 질문(입문용 개편안)을 백준 골드 4~5 문제 5개에 적용했다. 조건은 웹 검색(풀이 글 교차 확인)으로 확인했다. 토마토의 "모두 익지 못하면 -1"과 최단경로의 "같은 두 정점 사이에 간선이 여러 개일 수 있음"은 검색으로 확인하지 못해 알려진 조건으로 썼다.

|---|---|---|---|
| H | 백준 7576 토마토 (G5) | 여러 출발점 BFS | M×N 상자(2~1000), 1 익음 / 0 안 익음 / -1 빈칸. 하루에 상하좌우로 퍼질 때 모두 익는 최소 일수, 불가능하면 -1, 처음부터 다 익었으면 0 |

| J | 백준 1753 최단경로 (G4) | 다익스트라 | 정점 V(≤2만), 간선 E(≤30만), 가중치 ≤10, 시작점에서 각 정점까지 최단 거리, 못 가면 INF |
| K | 백준 2470 두 용액 (G5) | 정렬 + 투 포인터 | 서로 다른 정수 N(≤10만)개(-10억~10억), 합이 0에 가장 가까운 두 수를 오름차순으로 |
| L | 백준 9663 N-Queen (G4) | 백트래킹 | N×N 판(N<15)에 서로 공격 못 하게 퀸 N개를 놓는 방법 수 |

## 문제별 적용 (입문용 질문 그대로)

### H. 토마토

| 질문 | 통과하는 답 | 이 질문이 실제로 잡는 것 |
|---|---|---|
| 1 입력 | 첫 줄: 정수 M(가로) N(세로) / 다음 N줄: 정수 M개씩 (1, 0, -1) | **M, N 순서 함정**(N줄에 M개). 풀이 글에서도 자주 나오는 실수 |
| 2 출력 | 1줄: 최소 일수, 다 익었으면 0, 불가능하면 -1 | 특수 출력 두 가지(0, -1) |
| 3 규칙 | 모든 토마토가 익는 최소 일수 | **문제 문장을 다시 쓴 것뿐.** 어떻게 구하는지(동시에 퍼진다 → 여러 출발점에서 BFS, 가장 늦게 익는 칸의 날)는 묻지 않는다 |
| 4 손풀이 | 예제 1의 값 하나 바꾸기 → 6×4 격자를 처음부터 다시 퍼뜨려야 해서 오래 걸림 | 예제가 커서 "값 하나 바꾸기"가 부담. 2×2 같은 아주 작은 입력이 낫다: `1 0 / 0 -1` → 1일, `1 -1 / -1 0` → -1 |
| 5 구조 | 준비: 익은 칸을 모두 큐에 / 반복: 큐에서 꺼내 상하좌우의 0을 익히고 날짜+1로 넣음 / 출력: 0이 남았으면 -1, 아니면 최대 날짜 | 이게 풀이의 전부다. 사실상 "알고리즘을 쓰라"는 질문이 된다 |
| 6 경계 | 처음부터 다 익음 → 0 / 막혀서 못 익는 칸 → -1 | 잘 맞는다 |

파이썬: 칸이 최대 100만 개. 큐를 `list.pop(0)`으로 쓰면 시간 초과(`collections.deque` 필요). 5번 "가장 크면 몇 번"에서 잡을 수 있다.

### I. 평범한 배낭

| 질문 | 통과하는 답 | 이 질문이 실제로 잡는 것 |
|---|---|---|
| 1 입력 | 첫 줄: 정수 N K / 다음 N줄: 정수 W V | 쉽다 |
| 2 출력 | 1줄: 가치 합의 최댓값 | 쉽다 |
| 3 규칙 | 무게 합이 K 이하인 물건 조합 중 가치 합이 가장 큰 것 | **역시 문제를 다시 쓴 것.** 핵심(물건마다 넣는다/안 넣는다, "i번째 물건까지 보고 무게 w일 때 최대 가치"라는 상태)은 묻지 않는다 |
| 4 손풀이 | 작은 입력: K=4, 물건 (3,5) (2,3) (2,3) → 6 | **가장 가치 있는 질문.** 가치가 큰 것부터 넣으면 5, 정답은 6. 욕심쟁이 방법이 틀린다는 걸 손으로 확인하면 DP가 필요한 이유가 보인다. 다만 "예제 값 하나 바꾸기"로는 이 깨달음이 잘 안 나온다 |
| 5 구조 | 준비: 표 dp[무게] = 0 / 반복: 물건마다, 무게를 K부터 W까지 거꾸로 dp 갱신 / 출력: dp[K] | 점화식과 반복 방향(거꾸로)이 핵심인데, "준비/반복/출력" 틀에 들어가긴 한다 |
| 6 경계 | K보다 무거운 물건만 있음 → 0 | 잘 맞는다 |

파이썬: N×K = 1000만 번. 파이썬으로는 빠듯하다(2차원 표보다 1차원 표, 또는 PyPy).

### J. 최단경로

| 질문 | 통과하는 답 | 이 질문이 실제로 잡는 것 |
|---|---|---|
| 1 입력 | 첫 줄: 정수 V E / 둘째 줄: 시작점 K / 다음 E줄: u v w (u에서 v로, 방향 있음) | **방향 있는 간선**, 정점 번호가 1부터 |
| 2 출력 | V줄, i번째 줄에 i까지 거리, 못 가면 글자 INF | 특수 출력(INF 글자) |
| 3 규칙 | 시작점에서 각 정점까지 가장 짧은 거리 | 문제를 다시 쓴 것 |
| 4 손풀이 | 정점 3개: 1→2(5), 1→3(1), 3→2(1) → 0 2 1 | 바로 가는 길(5)보다 돌아가는 길(2)이 짧은 예를 직접 만들면, "가까운 정점부터 확정한다"는 생각으로 이어진다 |
| 5 구조 | 준비: 거리=무한, 시작=0, 우선순위 큐 / 반복: 가장 가까운 정점을 꺼내 이웃 거리 갱신 / 출력: 정점마다 한 줄 | 알고리즘 그 자체 |
| 6 경계 | 못 가는 정점 → INF / 같은 두 정점 사이 간선이 여러 개 → 짧은 것 | 잘 맞는다 |

파이썬: 간선 30만 줄을 `input()`으로 읽으면 느리다(`sys.stdin.readline`). 우선순위 큐는 `heapq`.

### K. 두 용액

| 질문 | 통과하는 답 | 이 질문이 실제로 잡는 것 |
|---|---|---|
| 1 입력 | 첫 줄: 정수 N / 둘째 줄: 서로 다른 정수 N개 (음수 가능) | 쉽다 |
| 2 출력 | 1줄: 두 수를 오름차순으로, 같은 답이 여럿이면 아무거나 | **오름차순** |
| 3 규칙 | 합의 절댓값이 가장 작은 두 수 | 문제를 다시 쓴 것 |
| 4 손풀이 | -5 1 3 → 합 -4, -2, 4 → -5 3 | 쉽다. 하지만 "왜 빨리 찾을 수 있나"로는 안 이어진다 |
| 5 구조 | 준비: 정렬, 왼쪽=처음, 오른쪽=끝 / 반복: 합이 0보다 크면 오른쪽을 한 칸 안으로, 작으면 왼쪽을 한 칸 안으로, 가장 0에 가까운 쌍 기억 / 출력: 끝나고 한 번 | 핵심은 "정렬하면 합이 크면 큰 쪽을 줄이면 된다"는 관찰인데, 어느 질문도 이걸 따로 묻지 않는다 |
| 6 경계 | 모두 음수 → 가장 큰 두 수 / N=2 → 그 둘 | 잘 맞는다 |

시간: 모든 쌍을 보면 N²/2 = 50억 번 → 불가능. **"가장 크면 몇 번"이 정답 방향을 정하는 질문이 된다.**

### L. N-Queen

| 질문 | 통과하는 답 | 이 질문이 실제로 잡는 것 |
|---|---|---|
| 1 입력 | 첫 줄: 정수 N | 공짜 |
| 2 출력 | 1줄: 방법의 수 | 공짜 |
| 3 규칙 | 같은 줄·같은 칸(열)·대각선에 둘이 없게 놓는 방법 수 | 대각선 판정(행 차 = 열 차)은 여기서 나온다 |
| 4 손풀이 | N=4 → 2가지 | 손으로 4×4를 다 해 보면 "한 줄에 하나씩 놓고, 안 되면 되돌아간다"는 백트래킹이 저절로 나온다 |
| 5 구조 | 반복(재귀): 줄마다 칸을 하나 골라, 열·두 대각선이 비어 있으면 놓고 다음 줄, 끝나면 되돌림 / 출력: 다 세고 한 번 | 재귀를 "준비/반복/출력"에 넣기 어색하다 |
| 6 경계 | N=1 → 1 / N=2, 3 → 0 | 잘 맞는다 |

파이썬: N=14에서 일반 파이썬은 시간 초과가 흔하다(PyPy로 통과하는 경우가 많음).

## 관찰: 골드에서 무엇이 달라지나

1. **1 입력, 2 출력, 6 경계는 그대로 가치가 있다.** 특히 골드는 특수 출력(-1, 0, INF, 오름차순)과 입력 함정(M·N 순서, 방향 간선)이 많아 1·2·6이 실제 오답을 막는다.
2. **3 규칙은 쓸모가 없어진다.** "출력 값을 어떻게 구하나"에 대한 답이 문제 문장의 반복이 된다(5문제 모두). 골드의 어려움은 "무엇을 구하나"가 아니라 "어떻게 빨리 구하나"인데, 그걸 묻는 칸이 없다.
3. **4 손풀이는 "예제 값 하나 바꾸기"로는 약하고, "아주 작은 입력을 직접 만들어 풀기"가 강하다.** 특히 "쉬운 방법이 틀리는 작은 예"(배낭의 욕심쟁이, 최단경로의 돌아가는 길)를 직접 만들게 하면 알고리즘이 필요한 이유가 손에 잡힌다. 입문 문제와 반대 결론이다.
4. **5 구조가 곧 알고리즘이다.** 학생이 알고리즘을 모르면 5번에서 막히고, 알면 5번이 사실상 풀이 전체다. 재귀(백트래킹)는 "준비/반복/출력" 틀에 잘 안 들어간다.
5. **"가장 크면 몇 번"이 골드에서는 가장 중요한 질문이다.** 두 용액은 이것만으로 "모든 쌍은 안 된다 → 다른 방법"이 정해진다. 입문용 개편안에서 "제한이 클 때만 묻는 덧붙임"으로 둔 것은 골드에서는 부족하다.
6. **답이 길어진다.** 5번은 2~3줄이 기본이고, LLM이 알고리즘의 맞고 틀림을 판단해야 해서 채점이 어렵고 틀릴 위험도 커진다(채점 노력 수준을 올려야 함).

## 제안: 칸 이름 6개는 그대로, 난이도에 따라 칸이 묻는 것을 바꾼다

기록 스키마(6칸)를 바꾸지 않고, "입문 세트"와 "도전 세트" 두 벌의 질문을 둔다.

| 칸 | 입문 세트 (브론즈~실버 하) | 도전 세트 (실버 상~골드) |
|---|---|---|
| 1 입력 | 줄마다 무엇 몇 개, 종류, 이름 | 같음 + **크기 제한을 함께 적기** |
| 2 출력 | 몇 줄, 몇 개, 구분 | 같음 + **특수한 경우의 출력(-1, 0, INF 등)** |
| 3 규칙 | 출력 값 하나를 어떻게 구하나 | **가장 단순한 방법은? 그게 가장 크면 몇 번이고, 시간 안에 되나?** |
| 4 손풀이 | 예제 값 하나를 바꾸면 출력이 어떻게 바뀌나 | **아주 작은 입력을 만들어 손으로 풀기. 가능하면 쉬운 방법이 틀리는 예로** |
| 5 구조 | 준비 / 반복 또는 갈림길 / 출력 | **무엇을 이용해 줄이나(핵심 관찰) + 뼈대.** 예: "하루에 동시에 퍼진다 → 익은 칸 전부에서 BFS" |
| 6 경계 | 틀리기 쉬운 입력과 답 | 같음 + **특수 출력이 나오는 입력** |

- 도전 세트의 3번이 "단순한 방법과 그 시간"을 묻고, 5번이 "그걸 무엇으로 줄이나"를 묻는다. 골드의 핵심 사고(완전 탐색 → 너무 느림 → 관찰로 줄이기)가 두 칸에 나뉘어 들어간다.
- 세트 고르기: 코드트리 난이도 표시(Easy 등)를 읽어 자동으로 고르고, 서랍에서 바꿀 수 있게 한다(난이도 표시가 실제로 어떻게 나오는지는 사용자 확인 필요 17번).
- 도전 세트 채점은 노력 수준을 올리고, 5번은 "알고리즘 이름을 맞혔나"가 아니라 "관찰이 맞고 뼈대가 그 관찰을 쓰나"로 본다. 2단계 힌트(방향)에서 알고리즘 이름을 말해 줄지는 정해야 한다(이름 자체가 큰 힌트).
- 파이썬 덧붙임(도전 세트): 큰 입력은 `sys.stdin.readline`, 큐는 `deque`, 재귀 깊이, 1천만 번 근처면 빠듯함을 5번 채점에서 짚는다.
